# PROD-06 核定：完整 CAS 是否属于原 WP70 剩余出口（2026-09-26）

> Document status: Active decision record（DOC 出口）。结论：**完整/跨进程 CAS 不属于原 WP70 已批准出口，属并发强化候选，不得自动排入开发**。

## 1. 依据（逐条引用）

- [工作包拆分 §2](./active-work-package-breakdown.md) WP70 行：“原文声明实现完成，WP90 外部场景待验；近期旧候选 guard 属补强”；关联行冻结的已实现范围为“同语句归属/发布读取、跨源校验、旧候选观察时点 guard”，并明确“**不等于完整 CAS**”。
- [安全执行状态 §25–§29](./security-development-execution-status.md)：§26 单语句归属读取（一条 LEFT JOIN，SQL.js 实测一次 SELECT）；§27 发布信息与归属同语句读取（唯一发布绑定 + 最新 profile 子查询）；§28 上游返回与捕获链跨源核验（固定拒绝所有权错配）；§29 旧候选激活读取时点 guard。§29 原文：“**这是读取时点 guard，不是跨进程 CAS**；未标记修改、计划前混读与完整执行快照仍未覆盖。”
- [调度规则 §4.6](./active-work-package-breakdown.md)：“CAS 等扩大要求先由 PROD-06 核对批准条款，不因最近报告写了‘仍缺’就自动纳入。”
- [未完成事项第 40 行](../reference/open-items.md)：“同源版本与后续验证/激活仍非完整 CAS 或整体一致事务；Watch、多进程、一致仓储读取及托管启动链接入、运行中撤销与自动逐跳/DNS 网络边界仍待完成。”

## 2. 核定结论

**原 WP70 已批准且已实现出口**（保留为回归维护，不再重开）：

1. 同语句归属/发布读取（§26/§27）；
2. 上游返回与捕获链跨源校验（§28）；
3. 旧候选激活读取时点 guard（§29）；
4. WP90 外部场景验证（EXT-07 真实失败候选保旧）为唯一原包剩余项，属环境验收。

**非原出口、属并发/一致性强化候选**（未批准，冻结不排期）：

- 跨进程/完整 CAS、整体一致事务、标记修改/计划前混读/完整执行快照；
- multi-process 一致仓储读取、PG 运行时跨进程 CAS 与掉电矩阵（与 OBS-14-05C3/PROD-04C 平台项边界另计）；
- 由上述推导出的“发布消费链路原子化”扩展。

## 3. 对台账与报告口径的影响

- 近期报告中的“完整 CAS 仍缺”表述应归类为**强化候选**，不得计入原 WP70 剩余出口或完成率分母；
- 若产品需要上述强化，须先通过独立 DOC/范围批准（含目标环境、并发模型与验收矩阵），再拆分执行；本记录不批准任何实现；
- [open-items](../reference/open-items.md) 第 40 行的“非完整 CAS”保留为事实陈述，并按其本身“仍待完成”的独立性质单独跟踪，不倒挂为 WP70 出口。

## 4. 出口

PROD-06 **DONE（DOC）**：完成核定与口径冻结；未新增代码、未改变任何运行时默认。
