# OBS-16-04 批量采集与投递联合验收

本轮基于oc_dev的5a9f227继续原计划：先减少source→终态事实的逐条SQL、扫描和状态成本，再减少outbox重复查询，并为统计提供有界推进预算。SEC-F4-02的文件监听迁移并行完成，见[安全证据](2026-10-08-security-file-watch-migration.md)。上一候选完整测量及失败边界保留在[宽等待证据](2026-10-08-observability-relaxed-timeouts.md)。

## 实际能力改动

- [采集批量SQL](2026-10-08-observability-ingest-bulk-sql.md)：每批仍至多16条，事务内预取并逐版本判定，事实/修订/事件/checkpoint分块写入。真实固定fixture SQL1475→163，autoSave仍4次；保留全部版本、源序列、期限、回滚和通用hook即时语义。该局部fixture不能直接换算端到端提速倍数。
- [扫描与统计公平预算](2026-10-08-observability-collector-fairness.md)：每文件64条量子、目录游标和有界续读队列，worker总128条/4MiB不变；持续积压每次1桶、按耗时冷却1～10秒，干净空闲每次8桶，metric/caller轮转；单桶读取最多5001条并对超5000条保留失败marker。半行/错误/积压仍禁止提前reconcile；持续超长半行或I/O故障仍优先当前文件，未承诺所有故障下绝不饥饿。
- [outbox](../../packages/api-nova-api/src/modules/call-observability/call-observability-outbox.service.ts)：保留32事件持久事务，将事件claim/materialized状态批量更新。按订阅ID/版本以128条keyset页取与本批序列范围相交的修订，逐事件重新选择最高有效版本并应用禁用/过滤条件。内存只保留一个订阅对最多32事件的有效版本；每32个job批量查重/插入。已有job状态和attempt不覆盖，事件状态、job、watermark同事务提交，仍不在事务中外发网络。
