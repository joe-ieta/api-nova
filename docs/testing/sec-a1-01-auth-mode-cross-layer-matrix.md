# SEC-A1-01 authentication-mode cross-layer matrix

Scope: local source snapshot captured before the SEC-A1-02A/C edits later on 2026-09-16, Windows, isolated tests. This is a contract inventory, not an end-to-end product acceptance or a claim that SEC-A1-02 is implemented. The Gateway and stdio gaps below describe that starting snapshot; [current leaf status](../guides/active-work-package-execution-status.md) and the [fifth-batch evidence](../audits/2026-09-16-replanned-batch-5-evidence.md) record the subsequent fixes. The target modes come from [security-development-task-plan.md](../guides/security-development-task-plan.md): Gateway `jwt`/`api_key`/`anonymous`; MCP HTTP `private_jwt`/`private_api_key`/`anonymous`; MCP stdio `local_process`.

## Cross-cutting findings and ownership

1. **High - mode selected versus mode executed (SEC-A1-02):** Introduce a typed inbound mode in MCP deployment DTO, persisted server policy, deployment/snapshot handoff, effective-mode response, and UI. Map `private_jwt` to JWT Bearer and `private_api_key` to `X-API-Key` only at the runtime adapter. Persist and display `local_process` for direct stdio if it becomes a managed product path. Avoid using `MCPServerEntity.authConfig` or the outbound Auth Manager as a substitute.
2. **High - Gateway public/anonymous mismatch (SEC-A1-02):** Choose one canonical visibility vocabulary across UI, DTO, persisted binding, compiler, summary, and runtime. Test saved `public`/`external`/internal combinations and display the effective mode, including the protected internal override. Clearing the UI text field currently sends `undefined`; the update path uses `dto.authPolicyRef ?? binding.authPolicyRef`, so an existing ref cannot be cleared through that form.
3. **High - invalid or missing modes can be saved (SEC-A2-01):** Gateway free-text ref is accepted at route configuration and rejected later by candidate compilation. Add a save-to-candidate-to-restart check for missing/unknown refs and malformed persisted snapshot objects; retain the last verified snapshot and make operator error explicit. MCP generic env rejects missing/unknown at request time; managed runtime rejects wrong mode before listening.
4. **High - temporary anonymous governance (SEC-A3-01):** No shared Allow Anonymous/Reason/Expires At/Created By record or expiry test exists. Do not treat explicit `anonymous` ref/global env alone as that approved policy.
5. **Medium - misleading adjacent fields (SEC-A1-02):** General server DTO `authConfig?: string` does not define an inbound mode; create path does not copy it into the server entity, while update uses broad assignment ([DTO](../../packages/api-nova-api/src/modules/servers/dto/server.dto.ts), [save](../../packages/api-nova-api/src/modules/servers/services/server-manager.service.ts)). The separate Auth Manager `none`/`bearer`/`apikey`/`basic` choices concern upstream API credentials; OAuth2 is disabled in its UI and rejected by write DTOs. They must be named as outbound credentials in the UI/API contract.
