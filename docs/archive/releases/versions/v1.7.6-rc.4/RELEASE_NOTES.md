# ApiNova v1.7.6-rc.4

> 发布状态：prerelease，供人工测试，生产签收未完成
> Git 提交：`@GIT_COMMIT@`
> 发布日期：2026-10-20
> 上一版本：v1.7.6-rc.3

## 核心变化

- 顶部健康徽标请求真实完整 `/health`，每30秒更新；正常显示健康，503显示异常，网络或无效响应显示未知。初次响应前不显示健康，不虚构数据库、WebSocket或版本信息。
- 顶部刷新在批量注册、手工注册、治理、发布、运行资产列表/详情、监控页面调用当前页面的数据加载函数，同时刷新健康；保留页面实例与未保存输入。其余页面明确标为“刷新健康状态”，不承诺刷新业务数据。
- 页面或健康请求失败不再提示刷新成功；重复点击合并保护，健康并发请求共用一次请求。
- 补齐带绝对server URL的OpenAPI JSON文件浏览器导入→治理→Gateway消费与监控分支；保留URL导入和手工注册回归。
- 整理当前未完成事项，已修复的模拟健康/通用刷新问题移出待办；日志页仍使用示例数据，明确列入维护队列。

## 兼容性与配置

无API、数据库schema或配置项变更。Vite增加`/health`代理，打包UI直接访问同源根路径；完整健康仍包含内存、至少空闲5GiB和MCP依赖，MCP未运行时显示异常是正常反馈。健康不可用不使已登录用户退出。

与rc.3保持相同数据迁移合同；仅接受已知迁移链的完整前缀，旧数据不自动复制到latest。保留Nest SSE字节补丁及实际依赖门禁。

## 平台产物与验证

本标签按统一发布流程交付Windows x64、Ubuntu 24.04 x64、Ubuntu 24.04 ARM64三个原生离线包，精确Node版本24.15.0、npm10.9.2。Linux基线为Ubuntu24.04。

- `api-nova-release-v1.7.6-rc.4-win-x64.zip`
- `api-nova-release-v1.7.6-rc.4-linux-x64.tar.gz`
- `api-nova-release-v1.7.6-rc.4-linux-arm64.tar.gz`

发布前必须通过锁文件安装、package-manager、runtime-closure、数据库初始化专项、全量测试、UI健康专项、类型检查、lint及生产构建。每个平台在匹配OS/CPU验证暂存启动及最终归档新解压启动，并阻断Node非回环TCP/DNS。实际结果和运行编号归档到本版本发布审计及evidence目录；任一门禁失败不晋升、不发布。

## 已知限制与人工测试范围

- SEC-F4-02、OBS-16-04及OPS-01目标/生产环境签收仍待办；当前使用本机隔离环境。
- 浏览器无server导入、认证规范、多端点、A/B迁移、MCP、多角色，以及二进制目标ACL/Linux文件语义/MCP真实外发仍未全部覆盖。
- 日志页当前为示例日志，不作真实审计依据；真实监控及运行资产访问日志按其对应接口使用。
- 配置、认证、API测试、日志及AI页面顶部按钮只刷新健康，页面业务刷新继续使用其已有入口。
- Nest维护迁移、依赖版本范围风险和lint警告继续维护；本次未为清零警告执行大范围重构。
- SQLite3000样本未证明有限窗口内全量采集投递，继续保留非阻断诊断；不声明生产容量保证。
- 真实SMTP/Webhook、反代/TLS、裸机systemd、长时多主机运行及独立API workspace安装仍按open-items签收。
- OAuth2、额外令牌适配和跨协议QoS继续延期。

## 升级与回退

先停止旧版本并完整备份配置、数据和日志，再在新目录解压测试。latest切换前完整备份旧latest至backups；不覆盖历史不可变archive或legacy数据库。回退时使用rc.3归档及与之对应的数据备份。

包内仅有公开本地测试默认值：账号`admin / admin@123456`，JWT默认值`api-nova-local-release-change-me`及`api-nova-local-release-refresh-change-me`；共享网络使用前修改这些值。发布物不得包含开发机.env、真实凭据或运行数据库。
