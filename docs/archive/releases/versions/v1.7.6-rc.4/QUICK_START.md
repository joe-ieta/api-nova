# ApiNova v1.7.6-rc.4 人工测试指南

这是候选测试版，尚未完成生产环境签收。选择匹配平台的离线包：Windows x64、Ubuntu24.04 x64或ARM64。

## 启动和停止

完整解压后，Windows运行`start.bat`，Linux运行`./start.sh`；无需安装依赖。浏览器打开 http://127.0.0.1:9001/ ，使用`admin / admin@123456`登录。

配置在`.env`，数据库在`data/api-nova.db`，日志在`logs/`，PID在`pids/`。在启动终端按Ctrl+C停止。共享网络使用前修改管理员密码及JWT_SECRET/JWT_REFRESH_SECRET，公开默认值分别为`api-nova-local-release-change-me`和`api-nova-local-release-refresh-change-me`。

## 建议人工测试顺序

1. 登录后检查顶部健康徽标。访问 http://127.0.0.1:9001/health 对照结果：200显示健康，503显示异常；暂时无法连接时显示未知。完整健康要求至少空闲5GiB，并检查内存及MCP。http://127.0.0.1:9001/api/health/live 仅代表API存活。
2. 在批量注册页从URL或JSON文件导入含绝对server URL的OpenAPI规范，检查文档和端点是否出现。
3. 点击顶部刷新，确认当前文档/资产列表重新读取，筛选和已打开的输入内容保持。手工注册、治理、发布、运行资产列表/详情和监控页也支持此刷新；其他页面按钮提示“刷新健康状态”。
4. 在浏览器开发者工具中临时阻断`/health`请求，再刷新：应显示未知及刷新失败；解除阻断后刷新应恢复。阻断文档或资产列表请求时不得提示刷新成功。
5. 完成端点实例探测、测试、准入、Gateway发布部署、创建消费凭证，再实际调用；检查认证拒绝、成功结果及监控中的对应请求。
6. 停止、重启，确认先前保存的文档和资产仍存在。另记录测试环境、版本、操作步骤、预期与实际结果、脱敏截图和日志。

日志查看页仍为示例数据，不用它判断真实调用结果。浏览器无server导入、认证规范、多端点、A/B迁移、MCP与多角色尚未全面验证；详细边界见RELEASE_NOTES.md。

## 排查与回退

检查9001和9022端口占用、平台/CPU及Windows C盘或Linux根目录可用空间；查看启动终端和`logs/`。MCP未运行导致完整健康503，不等于API启动失败。

升级前备份旧目录，勿将人工测试数据写入不可变archive。需要回退时用rc.3包与对应数据备份；latest晋升时保存的旧目录位于`api-nova-release/backups/`。
