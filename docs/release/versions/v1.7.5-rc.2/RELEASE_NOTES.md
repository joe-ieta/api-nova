# ApiNova v1.7.5-rc.2

> 发布状态：`prerelease`，Windows x64 单平台本地预发布
> Git 提交：`@GIT_COMMIT@`
> 发布日期：`2026-09-08`
> 上一版本：`v1.7.5-rc.1`
> 发布范围：`windows-only-preview`；用户已明确批准单平台例外

## 核心变化

- 合入并复核手工 API 注册、参数/请求体、MCP/Gateway 发布、治理失效及调用安全相关修改。
- 清除历史数据库、配置导入、会话和前端持久化兼容分支，删除未使用的模拟迁移界面与依赖。
- API 与迁移 CLI 统一环境加载和实体清单，PG/SQLite 均为 43 张业务表。
- 离线包使用初始迁移创建空库，不再依赖自动同步；当前库可重复启动，旧结构拒绝自动修复。
- Windows workspace 链接在 ZIP 前展开，启动使用内置 Node，不调用包管理器安装依赖。

## 已修复问题

- 补齐迁移清单遗漏的三张进程/健康检查表，修复 SQLite 枚举元数据反复重建表的问题。
- 配置导入严格校验当前格式，替换和审计在同一事务内完成，持久化失败不更新内存。
- 会话并发保存串行化，损坏或旧格式文件拒绝读取且不覆盖原文件。
- 开发启动不再自动激活、解锁已有管理员。
- 发布脚本显式加载包根目录配置；打包和冒烟均禁止自动同步，阻断非回环 Node 网络请求后验证实际启动入口。

## 兼容性与配置

- API/UI：保持本轮审查后的业务接口和真实配置页面；旧模拟迁移入口、派生 WebSocket 事件不再提供。
- 会话格式：`api-nova-sessions/v1`；配置导入格式：`config-overrides/v1`。旧格式不迁移。
- Header/Filter：仅接受当前结构化配置；CLI Header 使用 `KEY=VALUE`。
- 数据策略：初始开发阶段，不承诺历史数据库升级；使用新的空白数据库，不复制旧数据库到新包。
- `DB_SYNCHRONIZE` 必须为 `false`。首次运行执行本版本初始迁移，之后启动不会重建已有数据。
- 安全：默认测试账号 `admin / admin@123456` 与默认 JWT 密钥仅用于本机测试；共享网络前必须修改。
- Node：内置 Windows x64 `v24.15.0`；实际 Node/npm 精确版本、源码 SHA 和锁文件摘要记录在包内 `RELEASE_INFO.json`。

## 已知限制

- Linux、Ubuntu、外部 OAuth 提供方、真实上游完整发布和交互式 UI 验收未完成。
- 本地预发布不等于生产安全验收；依赖在线安全公告、备份恢复、留存与高并发故障场景仍需单独复核。
- 既有 UI 循环 chunk、第三方注释及依赖废弃警告不代表已解决。
- 旧版本文档中的依赖告警计数属于历史记录，本轮未用离线安装结果替代在线漏洞审计。

## 升级与回退

- 升级：停止旧实例，将本次 Windows ZIP 解压到新的目录，修改测试密码和密钥后运行 `start.bat`。
- 不复制旧数据库；若需保留旧数据，先独立备份并继续使用对应旧版本，本次不提供迁移。
- 回退：停止新实例，回到保留的旧版本目录或重新解压旧包，使用该版本自己的数据。
- 本次不移动或重建历史 `E:\CodexDev\api-nova-release` 目录。
