# 可观测性数据、配额与留存合同

本文合并原存储基础、生命周期和容量/配额合同中的有效约束。当前限定工程已完成；旧合同的partial/待实施阶段说明移入归档，不作为重新开发依据。生产配置和目标正确性仍归OBS-16-04。

## 数据链与统计口径

运行调用先形成源事实，再经采集、持久投影、事件、Outbox和投递。业务调用、HTTP ingress、工具、协议及物理上游attempt分别计量；管理/测试/探测等origin不能混入external业务流量。请求完成、终态入库、可查询、job入队和接收端收到是不同时间点。

幂等导入、同身份不同hash冲突、checkpoint、提交sequence与数据水位遵循原事务/恢复约束。失败必须保留真实结果，不能以补写新事实隐藏损失。Outbox只越过可证明已解决的事件；至少一次投递不承诺exactly-once。

## 保留与引用

| 对象 | 批准的默认/下限 | 约束 |
| --- | --- | --- |
| 调用及历史修订 | 默认30天 | 以已有expiresAt及策略快照为准，不能通过更新策略随意延长旧数据 |
| 正文 | 默认7天 | 逻辑到期立即影响读取资格；数据库引用、文件删除和失败补偿分开 |
| 事件 | 默认14天 | 过期不恢复发送资格；物理删除仍受delivery/租约/缺口证据保护 |
| 投递及其attempt | 至少30天 | 事件14天不能缩短投递审计；父子引用和历史修订需保留 |
| 管理审计 | 至少30天 | 幂等记录24小时到期不授权提前删除审计 |
| ingest receipt | 至少32天及原恢复约束 | 物理删除前要有可证明的去重/冲突墓碑或等价保护 |
| 已入库源暂存 | 证明完整导入后至少48小时 | 未导入、半行、活动或未知身份文件不能按mtime直接删除 |

逻辑过期不等于物理已删除；仍在途、引用不明、所有权不明或缺少证明时保留并报告。事件删除必须保留游标缺口语义，不能让旧游标得到假连续complete结果；全局sequence不回退或复用。策略修改不使失效正文或事件重新有效。

文件unlink不能与数据库事务原子回滚；恢复、墓碑、持久进度和失败报告共同保证可解释结果。不能凭一条cleanup请求或hasMore=false声称磁盘已完整回收。端点测试二进制对象属于独立合同，见[样例](publication-contract.md#二进制样例与留存)。

## 容量与配额

正文逻辑预算、扫描stat样本、文件系统实际占用和可用空间是四种量，不能互相替代。受控根内的临时/最终对象、预留预算和发布/撤销围栏按现有实现结算，不能将数据库和所有日志目录纳入一个虚构的全局硬盘配额。

配额发布门禁、恢复对账及状态报告已有对应子项证据，但默认开关、当前可用性和scanCoverage应读取有效配置/实际报告。complete只说明该次扫描的既定覆盖，不是文件系统原子快照；未知容量保持null/unknown，不能记0。启用配额不授权物理删除或下调保留下限。

## 状态与部署边界

管理心跳仅证明管理进程/Store回合；Gateway路由观察仅证明本进程注册范围。全局多实例水位、跨进程一致状态和无业务证据的存活继续unknown/null。Socket.IO已有事件与server_state_v1状态协议，但并不因此证明所有旧管理频道及多主机场景已签收。

PG3000本机全流程已有证据；SQLite3000有限窗口未全量，保留非阻断诊断，不承诺相应生产容量。时间阈值和参考硬件观察不作为新优化任务；完整性、持久化、授权、恢复和回退仍须满足原合同。
