## 1. 需求归纳与目标

以一套关联的调用记录，同时回答三个问题：

1. 本系统调用了哪些上游 API，实际发送和收到什么，失败发生在哪一层、哪次尝试。
2. 谁在什么时间访问了哪个 Gateway 路由或 MCP Tool，得到什么结果，如何回溯到相关上游调用。
3. 上层程序怎样通过查询接口与主动报送，持续获得访问活动、服务器状态、异常和数据采集完整性。

能力闭环为“采集、脱敏、汇集、检索、聚合、报送、复盘”。Gateway 与 MCP 共用身份、资产和可观测性模型，保留协议差异。大屏界面后续实现，本期提供它需要的数据接口、事件和一致性约定。

## 2. 当前基础与增强范围

依据前轮源码核查，以及现有安全调用、监控与产品约束文档整理。这里的“已有”表示存在实现或已声明的实现契约，不等于已在本轮进行运行验证。

| 能力 | 当前基础 | 本次增强 |
| --- | --- | --- |
| Gateway 外部访问 | Gateway 访问元数据表与查询接口；共享调用审计路径 | 统一调用明细、时间/调用者过滤、链路与字节统计 |
| MCP 与上游调用 | 共享审计记录支持 tool、api、admission，追加写入本地 JSONL | 按新格式持续汇集入库，区分工具、协议请求、上游实际尝试并关联 |
| Payload/Response | 当前审计契约已有正文、脱敏、采集状态与摘要；默认正文上限 16 MiB | 延续契约，增加受控正文查询、保留与容量治理 |
| 调用者 | 已有身份观察 JSONL 和 external-callers 清单接口 | 数据库增量维护；补充匿名来源、IP 观察、凭证关联与区间统计 |
| 运行状态 | 已有 runtime 状态、事件和指标实体 | 统一服务器状态、数据新鲜度、依赖失败与采集健康报告 |
| 实时消息 | 已有 /monitoring WebSocket 的运行事件和订阅 | 统一持久事件源、游标补拉、Webhook、投递记录与重试 |
| 审计复盘 | 现有 Gateway 元数据、JSONL、运行事件可作为证据 | 一次访问贯穿到工具、上游请求、相关状态与消息投递 |

注意：既有《安全调用与日志审计》的“改造前的能力缺口”是历史对照，不能直接当作当前未实现清单。正式实现时仍需以接入测试确认各分支覆盖情况。

本期扩展已有能力，不替换认证体系，不建设通用日志搜索平台，不引入必须部署的 Kafka、Elasticsearch 或其他独立基础设施。

## 3. 统一业务概念

| 概念 | 定义与计数边界 |
| --- | --- |
| 服务器 | 统一以 runtimeAssetId 管理，serverType 为 gateway 或 mcp；执行进程是运行实例，不是另一台业务服务器 |
| API 资产 | endpointDefinitionId 为稳定主标识；实际地址、绑定版本和上游实例是调用时快照 |
| 外部业务访问 | 一次 Gateway 请求或一次 MCP tools/call；二者可比较业务使用量 |
| MCP 协议请求 | initialize、tools/list、HTTP/SSE 连接、认证前拒绝等；独立于工具调用统计 |
| 上游实际请求 | 每次确实发出的 HTTP 请求；重试和重定向的每一跳独立记录 |
| 调用者 | 经认证的稳定主体；凭证和 IP 是它的关联信息 |
| 匿名来源 | 未认证访问的观察对象；IP、会话和 User-Agent 不等于真实用户 |
| 调用链 | traceId 下的父子调用记录；内部关联 ID 不依赖客户端自报 ID |
| 报送事件 | 已持久化的调用结果、状态变化、统计更新或采集异常通知 |
| 投递记录 | 某个订阅对某条事件的发送及接收端响应、重试与终态 |

“用户维度”在本功能中指调用者主体，不等同于 ApiNova 管理员账户。一次 MCP 工具调用产生三次上游尝试时，工具调用数为 1，上游请求数为 3。

## 4. 功能需求

### FR-01 上游 API 全过程跟踪

必须覆盖 Gateway 转发与 MCP Tool 触发的上游 API 请求，并按同一格式接入本系统内的 Endpoint 测试、探测和运行验证路径。测试/探测标记 origin=test 或 probe，业务流量标记 origin=external，默认业务统计不混入测试和探测。

每次实际请求记录 API 资产、上游服务/实例、展开后的脱敏 URL、方法、开始/结束时间、耗时、请求与响应、状态码、错误类别和所属父调用。不能可靠测量 DNS、连接、TLS 或首字节分段耗时时返回未知，不填零或推算为实测值。

必须区分输入校验、认证拒绝、DNS/连接/TLS 错误、超时、上游 HTTP 错误、响应解析错误、工具业务错误、客户端取消和流中断。记录可观测到的失败阶段和原因；未发出请求时不得伪造上游尝试。

重试保留每次失败和最终结果，并关联同一次逻辑上游操作。重定向、故障切换和并行依赖都要可解释。一次调用缓存命中时保留返回证据，上游请求数为零。

采集业务上游请求，不将日志投递、内部采集、指标查询等自发通信循环记作外部业务访问。

### FR-02 外部 Gateway/MCP 访问跟踪

Gateway 至少覆盖正常响应、未匹配路由、认证与权限拒绝、限流、缓存命中、上游失败、取消和响应中断。

MCP 至少覆盖工具调用的参数、结果、工具级错误和工具对应的上游 API。连接、协议操作及认证前拒绝另有记录。HTTP 返回 200 不能覆盖 JSON-RPC 错误或工具结果 isError。

尚未读取 MCP 正文即被拒绝的请求只记录已知的协议/准入信息，不猜测工具名或参数。STDIO 没有客户端 IP 时应明确为空，不能虚构网络调用者。

支持按访问者、时间、服务器、API、Tool、状态和链路查询；发布配置修改或资产删除后，仍能理解调用发生时访问的对象。

### FR-03 自动汇集调用者与来源清单

延续现有可信 JWT issuer/sub 和配置式 API Key subject 的归并方式。自动维护 firstSeenAt、lastSeenAt、认证类型、凭证记录引用、协议、访问过的服务器、来源 IP，以及调用计数和数据量。

只记录 credentialId 或受控的不可逆标识，不保存、显示或推送 API Key/JWT 原文。现有 Gateway 数据库 Key 如没有稳定 subject，保留凭证级主体，不能宣称已实现跨 Key 自动归并。

同一主体的多个 IP 不拆分成多人；同一 IP 的不同主体不自动合并。新旧凭证只有映射到同一个可信主体时才能自动归并。允许备注、标签和可审计的显式主体映射；历史证据不被改写。

匿名或认证失败流量维护“观察来源”清单，区分 unknown、anonymous、authentication_failed，不增加“已认证调用者数”。不对攻击者提交的任意伪造 Key 建立无上限的凭证实体。

客户端 IP 按可信代理配置解析，同时保存 socket peer、解析来源与可信状态。未受信任的 Forwarded/X-Forwarded-For 不能直接成为有效客户端 IP。

### FR-04 Payload、Response 与采集完整性

延续当前普通正文采集约定：JSON/表单语义完整保存，Header、Query、URL 和正文先脱敏；二进制与标准 multipart 按既有契约处理。每个请求侧/响应侧正文分别记录内容类型、编码、原始观察字节数、留存字节数、采集状态、脱敏策略版本和摘要语义。

默认正文上限继续为 16 MiB，配置上限 64 MiB。超过上限、未读取、解析失败、流中断、策略关闭、容量不足和已过期要返回不同原因；不能把正文缺失当作空正文。超限按当前契约省略正文，不悄悄改成前若干 KB 预览。

Gateway 入站请求和实际上游请求、上游原始响应和最终外部响应可能不同，应分别留存在各自调用边界。MCP 工具参数/结果与 HTTP 上游 Payload/Response 也必须分别可查。

正文留存与计数解耦：正文被省略或删除不应删除调用元数据或把已测流量改成零。查询列表、统计和推送默认不携带正文，正文由独立授权接口按需获取。

### FR-05 明细、链路与复盘 API

提供调用列表、单次调用详情、正文、完整调用链、调用者/来源清单，以及关联事件和消息投递查询。

支持多条件组合、游标分页和明确的排序。时间使用 UTC，区间统一为 [from, to)。详情记录原始来源、入库时间、当前契约版本及字段可用性，明确拒绝非当前格式，识别晚到记录和不完整链路。

支持失败优先检索，以及从一次外部错误逐层定位到上游尝试、响应内容或未调用上游的拒绝原因。对缺失父节点、历史正文过期和进程退出造成的不完整记录给出可解释结果。

“审计复盘”指查看历史证据与时序，不自动重放业务 API，避免再次产生业务副作用。批量原始正文导出不纳入首期。

### FR-06 聚合与可观测性 API

提供总览、时间序列、分组排行和服务器/调用者统计。必须支持访问次数、成功/失败/拒绝/取消次数、活动与唯一调用者数、请求/响应字节、耗时分布、上游失败与重试、缓存命中和当前执行中数量。

主要维度为时间、调用者、服务器类型/标识、API/Tool、上游实例和结果。各接口返回过滤条件、计数范围、时间基准、数据水位、计量方式和完整性，避免大屏把未知数据画成零。

外部业务访问、HTTP 入口流量、MCP 逻辑参数量和上游传输量分别统计。字节为指定应用边界的观察值或明确标注的序列化估计，不宣称为网络账单中的 TLS/TCP 线速字节。

唯一调用者数不能把各时间桶或两类服务器的数量相加；成功率和失败率必须公开分母；分位耗时必须标注精确或近似。无请求时比率为 null。

短期明细支持灵活过滤，长期聚合支持的维度和保留范围由 capabilities 接口说明。维度不可用或历史不完整时明确返回限制，不静默回落到不相干统计。

### FR-07 主动消息推送与消息留存

提供 Webhook 主动推送，并让现有 WebSocket 消费同一个持久事件源；REST 事件历史用于断线补拉、审计和不便接收推送的程序。

可订阅指定服务器、类型、API/Tool、调用者、事件类别、结果和严重级别。提供调用完成/失败、服务器状态变化、心跳/状态快照、统计桶更新、采集与投递异常。

持久化事件后发送。Webhook 采用至少一次投递，允许重复，消费者通过 eventId 去重；不承诺外部接收端恰好处理一次。每次发送记录开始/结束、耗时、响应码、脱敏错误摘要、下次重试时间和终态。

支持超时、退避重试、死信查询、人工重新投递与订阅暂停。订阅不可用不能阻塞 Gateway/MCP 业务请求。接收端返回成功仅表示已接收，不能宣称其业务处理已完成。

WebSocket 提供事件游标、补拉和过期提示，不为每个浏览器建立持久投递队列。主动状态报送来自运行心跳，不依赖持续存在业务流量。推送失败报警不得产生无限“报警投递失败再报警”循环。

### FR-08 服务器运行态势与大屏准备

服务器信息包含生命周期状态、健康状态、最近心跳、采集新鲜度、当前调用数、最近成功/失败、统计窗口和消息投递积压。区分“服务器离线”“没有业务请求”“日志采集滞后”和“上游失败”。

| 后续展示内容 | 所需接口/事件 |
| --- | --- |
| Gateway/MCP 总览卡片 | overview、servers/status、server.state_changed |
| 按时间的访问量、失败和数据量 | statistics/time-series、metrics.bucket_updated |
| 调用者活跃度、排行与服务器分布 | callers、sources、statistics/groups |
| API/Tool 热度和异常排行 | statistics/groups，保留稳定 API 与 Tool/发布快照 |
| 上游依赖与失败影响 | dependencies、traces、upstream 结果事件 |
| 实时访问/告警滚动列表 | events 历史与 WebSocket 订阅 |
| 点击访问记录开展复盘 | invocations 详情、payload、traces |
| 报送与采集健康 | deliveries、pipeline/status、pipeline.state_changed |

首次加载使用快照及其事件游标，随后订阅增量；断线先补拉，游标过期重新获取快照。按桶版本替换统计值，不能简单收到一次消息就加一次计数。

### FR-09 权限与日志自身的审计

沿用管理面认证，提供有明确资源范围的外部只读服务身份。业务调用凭证不自动获得管理日志访问权。

区分元数据查询、正文读取、订阅管理、重新投递、采集/保留策略配置。统计、游标、调用链和实时订阅均受相同资源授权约束。

正文读取、策略修改、主体映射、订阅变更和重新投递应产生管理审计事件。默认推送不包含正文、原始 IP、认证主体敏感字段或任何凭证。IP 的显示另受调用来源读取权限控制。

文件和数据库权限、受控备份与部署存储加密沿用平台能力。普通 SHA-256 摘要不能被表述为防篡改、第三方存证或不可抵赖保证。

### FR-10 保留、容量与可靠性

默认采用异步、失败放行；采集失败不能自动重发业务请求。必须公开排队、入库滞后、写入失败、隔离记录、丢失记录或已知缺口；不能宣称绝对零丢失。

采集队列、正文缓存、文件暂存、查询范围、订阅数和重试均有上限。达到上限时按策略降级并明确标记，而不是耗尽内存或静默丢弃。

建议初始保留：调用元数据 30 天、正文 7 天、分钟聚合 30 天、小时/日聚合 180 天、报送事件 14 天、投递与本功能管理审计 30 天。文件暂存对已入库内容建议保留 48 小时用于恢复。这些是已经确认的初始默认值，容量上限可能使正文提前省略或过期，必须可见。

调用者及来源身份和 IP 观察默认在最后活动 180 天后清理，前提是无仍在保留期内的明细引用；长期统计需要的不可逆聚合键与身份信息分离。正文备份的有效保留规则与在线存储一起制定。

## 5. 部署边界与非功能要求

首期覆盖现有单管理实例、单主机多进程运行方式，支持 SQLite 与 PostgreSQL、Windows 与 Linux。独立 MCP Server 写相同审计格式，由同机采集器或受控导入汇集；多主机远程采集协议为后续扩展，不默认为已经支持。

| 指标 | 拟验收目标，非当前实测 |
| --- | --- |
| 采集可见性 | 正常负载下，完成记录至可查 p95 不超过 3 秒 |
| 首次报送 | 正常负载和健康接收端下，完成记录至首次 Webhook 尝试 p95 不超过 5 秒 |
| 状态心跳 | 默认 15 秒；连续 45 秒无心跳标记 stale/unknown，再结合管理器判断 offline |
| 业务开销 | 固定基准负载下采集导致的额外 p95 延迟目标不超过 10 ms |
| 查询 | 指定容量与索引条件下，明细列表和常用聚合 p95 目标不超过 2 秒 |
| 参考验证负载 | 4 核/8 GiB/本地 SSD，100 请求/秒、每次请求加响应不超过 8 KiB；记录数据库与持续时间 |
| 可靠性边界 | 对已被收集并提交到数据库的事件，可恢复且幂等；进程强杀前未持久化数据仍可能缺失 |

性能目标必须在确认后的实现阶段用有代表性的负载验证。高并发大正文、持续长流与 SQLite 的容量上限单独报告，不能从小正文基准外推。

## 6. 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | Gateway 正常调用上游 | 一条业务访问、一条上游请求，可查各自正文与父子关联 |
| AC-02 | MCP Tool 触发两次失败重试后成功 | 一个工具调用、三次上游请求；顶层成功，失败尝试仍可审计 |
| AC-03 | 缓存命中、路由未匹配、权限拒绝 | 外部访问有结果，没有伪造上游请求；MCP 认证前拒绝单独计入协议入口 |
| AC-04 | DNS/连接失败、超时、取消、流中断 | 正确分类，未知耗时/字节不填零；未收到 Response 有明确状态 |
| AC-05 | HTTP 200 且工具 isError 或 JSON-RPC 错误 | 工具失败数增加，不被 HTTP 成功覆盖 |
| AC-06 | 同主体换 Key/IP，不同主体共享 IP | 按可信主体归并；匿名和失败来源不混入已认证人数 |
| AC-07 | 伪造代理 Header、恶意 Key | 不提升身份可信度，不产生无界凭证目录 |
| AC-08 | JSON/Query/multipart/二进制/超限正文 | 脱敏与状态正确；大于 4 KB 的普通正文仍可完整留存；省略不影响已测字节 |
| AC-09 | 重复文件导入、部分尾行、采集器重启 | 已提交调用和统计不重复，部分行等待补全，损坏记录隔离并可追踪 |
| AC-10 | 进程在开始后被强杀，晚到完成记录随后到达 | 先呈现未知/不完整；真实终态修正一次统计，不多算调用 |
| AC-11 | 多服务器、多时间桶、同一调用者 | 去重人数、调用量、字节和分母符合公开口径 |
| AC-12 | Webhook 超时或成功响应丢失 | 有重试记录；重复消息保留同一 eventId；业务请求不受阻塞 |
| AC-13 | 重启投递器、暂停订阅、死信重新投递 | 状态可恢复、权限有效、尝试历史保留、无事件失踪 |
| AC-14 | WebSocket 断线、游标过期、过滤变化 | 可补拉或明确重建快照；无越权历史、无重复累计 |
| AC-15 | 数据库不可用、磁盘配额耗尽、采集滞后 | 公开健康异常和缺口，有限降级，不反复调用上游 |
| AC-16 | 正文/事件到期清理 | 元数据/聚合仍有效，正文状态为 expired，旧事件游标有明确过期响应 |
| AC-17 | 非授权查询、正文读取、实时订阅 | 统一拒绝；有权限的敏感读取和管理变更可追溯 |
| AC-18 | Endpoint 测试/探测、后台日志报送 | 分别标记 origin；默认外部业务统计不受污染 |
| AC-19 | 无业务流量但服务器运行 | 状态心跳持续；零流量与采集故障明确区分 |
| AC-20 | SQLite/PostgreSQL、Windows/Linux | 使用相同字段和统计语义，STDIO stdout 不被审计污染 |

## 7. 实施顺序与确认范围

1. 接入与证据：统一契约、上下游边界、身份来源、增量汇集、幂等、正文治理。
2. 查询与分析：明细/正文/调用链/调用者/聚合 API，权限、保留与采集健康。
3. 状态与报送：持久事件、Webhook、投递记录、重试、WebSocket 补拉及快照。
4. 集成与验收：场景验证、负载验证、旧能力收敛及接口文档；不增加兼容适配层。

以上步骤均属于确认后的同一期后端能力交付；不是把主动推送另行推迟。大屏 UI、多主机收集、外部消息总线、批量正文导出、自动业务重放和第三方防篡改存证不纳入本期。

本文边界、配套设计、正文采集与保留建议、Webhook/Socket.IO 接入方式及首期部署规模已由用户确认。开发任务计划和 Endpoint 细化也已获用户确认，现按依赖实施。后续按全新开发版本统一收敛，常规实现选择不再重复征求确认。
